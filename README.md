# alpoker-mtt-sim

身内で遊ぶ、5人卓のポーカー疑似トーナメント（40人・8卓・CPU入り）。

- **ひとりで遊ぶ**: `index.html` をブラウザで開くだけ（サーバー不要）
- **みんなで遊ぶ（簡易サーバー）**: サーバーが部屋を持つ。誰かのブラウザを開きっぱなしにしなくていい（下の「簡易サーバー」）
- **みんなで遊ぶ（サーバーなし）**: ホストのブラウザが部屋を持ち、参加者は部屋ID＋パスワードで入室（PeerJS / WebRTC）

どちらになるかは自動で決まる。簡易サーバーから配信されたページならサーバー、ファイルを直接開いたときなどは PeerJS。

## ログイン（簡易サーバーだけ）

Discord か Google でログインできる（`account.html`）。ログインしなくても、今まで通りゲストとして遊べる。

- 身内の Discord サーバーのメンバーは、招待なしで Discord から入れる。それ以外は、管理者が出した招待リンクから入る
- 同じ人が Discord と Google の両方を使うときは、ログインしたあとにアカウント画面で「連携する」（メールアドレスでの自動の紐づけはしない）
- メールアドレスは受け取らない。保存するのは、外部サービスでの ID と表示名・アイコンだけ
- 仕組みは `server/auth.js`（ログインの流れ）と `server/accounts.js`（保存）の先頭のコメント、設定は [`deploy/README.md`](deploy/README.md) の「7. ログイン」

### ログインして遊ぶとき

| | ログインしている人（メンバー） | ゲスト |
|---|---|---|
| 部屋を作る | できる（合言葉は要らない）。「ゲストも入れる」を選んだときだけ、ゲスト用のパスワードを決める | 部屋を作る合言葉（`CREATE_KEY`）とパスワードで作る（これまでどおり） |
| 入室 | 名前もパスワードも要らない（アカウントの表示名で入る） | 名前とパスワード。メンバーの表示名と同じ名前は使えない |
| 入り直し | 同じアカウントなら、別の端末からでも同じ席に戻る。前の画面は止まる | 同じタブなら、復帰用の合言葉で同じ席に戻る |
| 開始・退出させる | 部屋を作った人と、サイトの管理者 | 合言葉で部屋を作った人 |

- 退出させたアカウントは、その部屋には入り直せない
- 別のサイトのページからの接続は、Cookie が付いていてもゲストとして扱う（なりすまし防止）
- 大会結果のファイルに、アカウントの ID と打ち方の記録（VPIP など。身内CPU作りの材料）を残す。参加者に送る履歴には、アカウントの ID は入れない

## ひとり用の記録をアカウントへ送る（簡易サーバーでログインしているとき）

簡易サーバーのページでログインしてひとり用を遊ぶと、ハンドが終わるたびに、そのハンドと打ち方の記録をアカウントへ送る（あとで傾向を見る・身内CPUの材料にするため）。

- 最初の画面の「ひとり用の記録を送る」で止められる（はじめは ON）
- 送れなかった分はブラウザに溜め、次のハンド・次に開いたとき・ネットにつながったときに送り直す（まだ送れていない数を、同じ場所に出す）
- 溜めた分には「誰のアカウントの分か」を付ける。別の人がログインしても、その人の分としては送らない
- サーバーは届いたものを厳しく検める（形・数・大きさ。知らない欄は捨てる）。「あなた」の席のアカウント ID はサーバーが付ける
- ファイルを直接開いたとき・ログインしていないときは、何も送らない（今までどおり）
- 仕組みは `solo-sync.js`（ブラウザ）と `server/solo.js`（検め）

## ハンドを見返す（簡易サーバーでログインしているとき）

トップ画面の「ハンドを見返す」（`hands.html`）。参加した大会のハンドを、卓の絵で1手ずつ再生する。

- 大会を選び、ハンドを選ぶ（ショーダウン・自分がオールイン・大きなポット・自分から参加・位置で絞り込み）
- 最初・前へ・次へ・最後・自動再生。キーボードは ← →（1手）、Shift + ← →（前後のハンド）、Home / End
- 手札は、そのとき見えていたもの（自分の手札・ショーダウンやオールインで表になった手札）だけを出す。「全員の手札を表示」で全部（終わった大会だけ）
- アドレスに大会とハンドが残る（`hands.html?t=大会&n=ハンド`）。振り返り画面の1ハンドからも「卓で再生」で開ける
- 見える範囲は振り返りと同じ（続いている大会は、自分のハンドの、自分の手札と公開された手札だけ）
- コマ作りは `engine.js` の `replayFrames`（どのコマでもチップの合計が変わらないことをテストで確かめている）

## スポット（簡易サーバーでログインしているとき）

トップ画面の「スポット」（`spots.html`）。同じ場面に、みんながどう打つかを集めて並べる（GTO の解ではなく、人間の選択と理由）。

- プリフロップの問題は自動で作る（5-Max・10/13/16/20/25BB・アンティ 0.2BB）。シナリオは「オープンするか」「オープンへの対応」「3bet への対応」の3つ
- 判断が割れる手だけを出す（22〜JJ・A2s〜A9s・A2o〜AJo・ブロードウェイの一部・54s〜T9s）。BTN は出題しない
- 成り立たない場面は作らない（BB のオープン・BB の 3bet 対応・10BB の 3bet 対応）
- 各自が好きなだけ答える（全員に回答は求めない）。「次の問題」は、前に答えたのと違う種類（プリフロップ・ポストフロップを交互）で、評価が高い問題 → 他の人が答えた問題の順に出す。答えていないものがなくなったら新しく作る
- 答えたあと、問題を「良い問題」「悪い問題」で評価できる（1人1票、取り消し可）。お気に入りに入れることも良い問題1票と同じに数える（評価 = 良い − 悪い ＋ お気に入りの数）。評価が −2 以下の問題は「次の問題」に出さない
- 問題には大会の状況（40人エントリー・入賞8人・残り2〜30人と、平均の持ち点）を添える。バブル付近（残り9〜11人）・入賞圏内・最終卓も出し、画面にそう示す。そこでは CPU も入賞を意識した判断になる
- 卓の人数はゲームと同じ決め方（残り人数を5で割って切り上げた数の卓に、人数差1以内で座る。例：残り7人 → 4人卓か3人卓、6人 → 3人卓）。プリフロップの出題席はその卓にある席から選び、ヘッズアップは SB がボタン。ポストフロップは、人数の少ない卓ほどフロップ以降まで残りやすいので、ヘッズアップと3人卓は間引く
- お気に入り：問題の画面で「☆ お気に入りに入れる」（答える前でも入れられる。アカウントごと）
- マイページ（`spots.html?me=1`）：答えた問題の数、多数派と同じだった割合、答えの傾向（ベットを受けたとき・受けていないときの、降りる／受け身／攻めるの割合を、同じ問題のほかの人と比べる）、お気に入り、ほかの人と答えが違った問題（ほかの人が2人以上答えていて、その 2/3 以上が違う行動）
- サーバーは、まだ誰も答えていない問題を種類ごとに3問ずつ作り置きする（少ないほうの種類から作る）
- リンプの判定を入れる前に作った問題のうち、まだ誰も答えていないリンプのポストフロップは、起動時に片付ける（答えがついた問題は残す）。消えるのは更新後の最初の起動のときだけなので、更新は、誰も問題を開いていないときに行う（開いたままの問題に答えると「その問題はありません」になる）
- 回答は1人1回で、理由のコメントは必須。答えるまで他の人の答えは見えない。答えるとすぐ結果が見えるので、あとから直せない
- 結果はグラフにせず、全員の選択とコメントを並べる
- ポストフロップも自動で作る（プリフロップと半々）。ゲームと同じ CPU（`engine.js` の `hand`・`ai2`）で1ハンドを進め、あなたの番（フロップ 45%・ターン 35%・リバー 20%）で止めて写す
  - 乱数はシード1つから作る（`engine.js` の `seeded`・`withRandom`）。配札・席順・CPU の個人差と行動のすべてが同じシードなら同じになる。問題にはシードを残す
  - あなたの手前の行動（プリフロップなど）は、あなたの席に「バランス」タイプの CPU の判断をさせて進める
  - 自明な場面は出さない（ベットを受けていて、ワンペアもドローもない）。ベットを受けていない場面は出やすいので半分に間引く
  - リンプのあった場面は出さない（CPU は入るときに3〜4回に1回リンプするが、実戦ではまれ）。SB と BB の2人きり（ヘッズアップや、前の全員が降りたとき）で揃えるのは残す
  - 自分のドンク（前のストリートの攻め手がまだ動いていないのに、先に打つか）は 5% だけ残す（ポストフロップの問題の約2%）
  - 答えは、ベットを受けていれば フォールド・コール・レイズ、受けていなければ チェック・ベット（オールインはいつでも）
- まだないもの：GTO 解の表示、ポストフロップの手動投稿、Discord への通知、人ごとの傾向
- 問題作りと API は `server/spots.js`（DB は `spots`・`spot_answers`・`spot_votes`・`spot_favs`）

## 振り返り・打ち方の傾向（簡易サーバーでログインしているとき）

`review.html`（最初の画面の「振り返り・傾向」）。

- **大会とハンド**：参加した大会（みんなで遊ぶ・ひとり用）の一覧 → ハンドの一覧（ショーダウン・自分がオールイン・大きなポット・自分から参加・位置で絞り込み）→ 1ハンドの表示。絞り込んだハンドをテキスト / JSON で保存
  - みんなで遊ぶ大会がまだ続いているあいだは、自分が配られたハンドの、自分の手札と公開された手札だけ。終わったら全員の手札
- **打ち方の傾向**：ハンド履歴から数え直した13項目（VPIP・PFR・3ベット率・AF など）と、位置別・スタックの深さ別。合算・対人・対CPU、期間（全期間・30日・90日）を選べる
  - 数え方は `engine.js` の `analyze`。遊びながら数える `track` と同じ結果になることをテストで確かめている（離席が混ざったハンドは数えない）
- **身内CPUの材料**：傾向を `alpoker-profile`（ひとり用の「あなたの傾向」のエクスポートと同じ形）で書き出す。位置別・深さ別も入る
- **他の人の傾向**は、その人が「身内CPU化に使ってよい」にしたときだけ見られる・書き出せる（本人が `review.html` の傾向のところで決める）

## ハンド履歴

ゲーム画面の下の「ハンド履歴：テキストで保存 / JSONで保存」で、自分が配られたハンドを保存できる。

| | 大会中 | 大会が終わったあと |
|---|---|---|
| ひとりで遊ぶ | 全員の手札つき（相手は CPU なので） | 同じ |
| みんなで遊ぶ | 自分が配られたハンドだけ。見えるのは自分の手札と、公開された手札だけ | 全ハンドを全員の手札つき（振り返り用） |

簡易サーバーでは、**ハンドが終わるたびに**記録の DB（`DATA_DIR/alpoker.db`、SQLite）へ書く（大会・参加者・順位・打ち方の記録・全ハンド）。表の形は `server/db.js`、書き方は `server/records.js`。
大会が終わると、全ハンドを `DATA_DIR/hands/日時-部屋ID.json` にも残す（形の版は 2。参加者とハンドの各席にアカウントの ID〈ゲストは null〉、参加者に打ち方の記録 `stats`）。以前のファイルは、起動したときに DB へ取り込む。
形式は `engine.js` の `histText` の上のコメントを参照（JSON は身内CPU作りなど、道具に渡す用）。

## ファイルの役割

| ファイル | 中身 | 画面 | 通信 |
|---|---|---|---|
| `engine.js` | ルール・役の判定・CPU・大会の作り方（`AlpEngine`） | 触らない | 触らない |
| `room.js` | みんなで遊ぶ部屋：大会の進行（`createRoom`）と入室の受付（`createHost`）（`AlpRoom`） | 触らない | 触らない |
| `net.js` | 通信の口（PeerJS 版 `PeerLink`・WebSocket 版 `wsLink`）と入室の手順（`joinRoom`） | 触らない | ここだけ |
| `game.js` | ひとり用の画面と進行 | ここ | — |
| `mp.js` | みんなで遊ぶの画面とロビー | ここ | `net.js` 経由 |
| `hands.html` / `hands.js` | ハンドを見返す（卓の絵で1手ずつ再生） | ここ | `server/review.js` |
| `review.html` / `review.js` | 振り返り・打ち方の傾向の画面 | ここ | `server/review.js` |
| `spots.html` / `spots.js` | スポット（同じ場面に、みんながどう打つか） | ここ | `server/spots.js` |
| `solo-sync.js` | ひとり用の記録をアカウントへ送る（簡易サーバーでログインしているとき） | 少し（送るかどうかのチェック） | ここ |
| `server/server.js` | 簡易サーバー：ページの配信と部屋（`room.js` の `createHost` を WebSocket につなぐ） | — | ここ |
| `server/store.js` | サーバーの小さな保存先（`data/store.json`） | — | — |

`engine.js` と `room.js` はブラウザでも Node でも動く（`require("./engine.js")`）。
部屋の受付と進行は、ホストのブラウザでもサーバーでも同じ `room.js` を使う。違うのは「どう届けるか」だけ。

ビルドは不要。読み込み順は `index.html` のとおり（engine → room → net → game → mp）。

## 簡易サーバー

Node 22 以上で:

```bash
npm ci
CREATE_KEY=身内だけの合言葉 npm start
```

`http://localhost:8080` を開く。部屋を作る人は「部屋を作る側はこちら」から、名前・パスワード・合言葉を入れて作る。
作った人だけが「ゲーム開始」と「退出させる」を操作できる（再読み込みしても、その権限ごと同じ席に戻れる）。
ログインしていれば、合言葉なしで部屋を作れる（上の「ログイン」）。

| 環境変数 | 既定 | 意味 |
|---|---|---|
| `PORT` | 8080 | 待ち受けるポート |
| `HOST` | 0.0.0.0 | 待ち受けるアドレス |
| `CREATE_KEY` | なし | 部屋を作るときに必要な合言葉。**外に公開するなら必ず設定する** |
| `DATA_DIR` | `./data` | 保存先のフォルダ（ネームドCPUの記憶・ハンド履歴 `hands/`） |
| `MAX_ROOMS` | 20 | 同時に開ける部屋の数 |

- 外から使うときは、前に HTTPS を受け持つもの（Caddy や nginx など）を置く。WebSocket（`/ws`）も通すこと
  - VPS への置き方（今 `https://kaina-lab.com/poker/mtt/` で動いている構成）は [`deploy/README.md`](deploy/README.md)
  - `/poker/mtt/` のような途中のパスに置いても、そのまま動く
- 誰もいなくなった部屋は 10 分で片付ける
- **サーバーを再起動すると、遊んでいる途中の大会は消える**（部屋はメモリ上にあるため）。大会中の更新は避ける

## テスト

```bash
npm ci
npm test
```

Node 標準のテスト機能を使う。サーバーのテストだけ `ws`（`npm ci` で入る）を使う。
大会を早送りの時計で最後まで回して、チップの合計・手札が漏れていないか・切断や復帰・入室の手順を確かめる。

PR を出すと GitHub Actions でも同じテストが回る（`.github/workflows/test.yml`、Node 22 と 24）。
